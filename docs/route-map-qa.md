## 브라우저 증적

실제 앱 컴포넌트에 합성 일정 11개를 제공하는 로컬 QA 서버를 사용했다. 실제 Notion 여행·좌표·PIN을 저장하거나 공개하지 않았다. 배경은 실제 OSM London 타일이다. 이 합성 좌표는 제품의 동적 데이터 처리 검증용이며 운영 데이터 대체가 아니다.

- PC 약 1234px: 지도/목록 좌우 배치, 실제 타일 9개 로드, 번호·점선·출처 표시 확인.
- 모바일 390×844: 지도 위/목록 아래, 페이지 가로 넘침 없음(문서 폭 375, viewport 390). 날짜 전환 및 목록 제공 확인. 실제 휴대폰 터치 검증은 미수행.
- 기본 타임라인에서는 `.leaflet-tile` 0개. 지도 진입 후 첫날 마커 6개/일정 8개, 점선 1개. 3번 위치 누락에도 후속 번호 4/5/6 유지.
- 둘째 날 마커 2개, 점선 1개. 전체는 마커 8개, 점선 2개이며 날짜 사이 연결 없음.
- 목록 선택 → 지도 이동/팝업, 겹친 1/5/6번 선택 목록 → 해당 일정 강조와 팝업 전환 확인. HTML처럼 생긴 제목은 문자열로 표시.
- reload 후 전체 선택/지도 보기 유지. 타임라인의 결과 없는 검색어가 지도 전체를 숨기지 않음.
- 합성 API 좌표 수정 후 새로고침 시 전체 마커 9개/점선 4개로 갱신. 다른 여행은 기본 타임라인이며 첫 여행 설정과 분리.
- 좌표 없는 여행은 지도 0개, 위치 등록 안내와 일정 목록 제공. 합성 API 401 후 PIN 입력 화면, 지도 0개 확인.
- 타일 실패 전용 서버 재시작 뒤 브라우저의 localhost 연결이 실패하여 장애 화면/재시도는 검증 완료하지 못했다. 오류 분기와 12초 타임아웃·재시도는 구현했고 수동 재검증 필요.

PC/모바일 캡처는 작업 완료 응답에 첨부한다. 운영 화면의 before/after 또는 실제 해외 여행 좌표 검증 캡처로 해석하지 않는다.

## 추가 설정과 운영 전 확인

연결된 일정 DB 스키마에 `위도`/`경도`가 없음을 확인했으며 자동 추가하지 않았다. 사용자가 선택적 Number 속성 두 개를 추가하고 확인된 WGS84 좌표를 등록해야 한다. 앱 integration은 기존 읽기 권한을 유지한다. 지도 신규 필수 환경변수는 없다. 공급자 교체용 공개 변수와 URL 좌표 규약은 README 참조.

기본 OSM 표준 타일은 출처·Referer·브라우저 캐시를 유지하고 벌크/미리받기를 하지 않는다. SLA/중국 접속/무료 무제한을 보장하지 않는다. [Leaflet 문서](https://leafletjs.com/reference-1.9.4.html), [OSM 이용 정책](https://operations.osmfoundation.org/policies/tiles/)을 기준으로 구현했다. 운영 전 대표 해외/국내 지역의 WGS84 좌표 정합성 및 현지 통신망, 예상 트래픽에 맞는 타일 약관·비용 확인이 필요하다.

## UI 재검증 방법

`node scripts/route-map-qa.mjs` 실행 후 터미널에 출력된 로컬 URL을 연다. 이 서버는 개발 전용이며 실제 API 인증을 대체하므로 운영 배포에 사용하지 않는다. 실제 제품 빌드/서버에서 이 스크립트를 import하지 않는다.

`/qa/update` 방문 후 앱 새로고침으로 좌표 갱신, `/qa/expire` 후 새로고침으로 인증 만료를 재현한다. 프로세스를 다시 시작하면 초기 데이터로 복구된다. `--failed-tiles`는 실패 타일 URL을 사용하는 별도 5180 포트다. 필요 시 환경변수 `ROUTE_QA_PORT`로 포트를 지정한다. 장애 안내·지도 다시 시도·타임라인 복귀를 추가 확인한다.
