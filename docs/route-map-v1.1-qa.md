## 데이터 확인

연결된 Notion 여행 일정 data source를 읽기 전용으로 확인했다. `활동` text/rich_text, `동선 순서` Number 및 위도/경도 Number가 존재한다. 전체 76건, 활동 76건, 좌표쌍 28건, 유효한 명시 순서 8건이며 조회에 추가 페이지는 없었다. 좌표가 입력됐다는 사실은 위치의 정확성이나 WGS84 전수 확인을 의미하지 않는다.

실제 행을 메모리에서만 모델에 대입해 새 속성 호환성을 확인했으며 장소/좌표/메모를 fixture나 공개 로그에 저장하지 않았다. 명시된 오프셋을 유지하고 임의 시간대를 적용하지 않은 검증에서 8개 계획 후보가 보존됐다. 앱의 운영 integration 토큰으로 보호된 v1.1 API를 조회한 검증은 아니며, 실제 배포 후 새로고침 검증은 별도다.

## 정렬 및 연결 정책

- 모든 방문 후보의 유효·고유 routeOrder가 있을 때 계획 순서를 사용한다. 표시 번호는 정렬·그룹화 후 1부터 부여하고 입력 숫자 10~80을 그대로 번호로 쓰지 않는다.
- 혼합 일자는 실제 시각을 기본으로 하며 시간 미정 후보를 UUID나 생성순으로 끼워 넣지 않는다. ID는 표시를 안정화하는 보조 기준일 뿐이다. 미확정 후보가 있거나 중복/시각 충돌을 발견한 날은 전체 점선을 보수적으로 보류한다. 다른 날짜에는 영향이 없다.
- 같은 이름이어도 서로 다른 주소/좌표가 있으면 묶지 않는다. 시설 내 매장은 동일 시설임이 명시된 이름 계층과 동일 대표 좌표가 있을 때만 묶는다. 확인할 수 없는 동일 좌표의 다른 상호는 겹침 선택 UI를 유지한다.
- 이동 구간의 시작·끝이 인접 방문의 정확한 제목/장소와 대응할 때만 확인된 연결로 취급한다. 경유지·상충 설명·확정할 수 없는 위치를 문자열에서 추측하지 않는다. 좌표 누락 방문을 가로질러 연결하지 않는다.
- 시간/순서 없는 같은 장소들은 연속 방문임을 입증할 수 없어 자동 통합하지 않는다. 원본 타임라인과 모든 eventIds/활동은 보존한다.

## 브라우저 증적

실제 앱 UI + 개발 전용 합성 API + 실제 OSM 타일로 PC 약 1234px 및 모바일 390×844를 확인했다. 캡처는 완료 응답에 제공한다. fixture는 운영 여행이 아니며, 원본 Notion 정보나 PIN을 담지 않는다.

- 타임라인 기본/타일 요청 0개, 장소명 아래 활동, 활동 검색, 이동 구간 표시 및 기존 원본 일정 보존 확인.
- 첫날 일정 10건 → 방문 그룹 6곳/마커 5개/점선 1개. 2개 연속 활동이 한 그룹이며 이동/취소/집은 번호를 소비하지 않는다. 누락 3번 이후 마커 4/5/6을 유지하고 불확실한 선을 생략했다.
- 둘째 날 시간 미정 8개 → 1~8 마커/점선 7개, 시각 생성 없이 계획 안내. 전체는 마커 13개/점선 8개이며 날짜 사이 선이 없다.
- 목록 클릭·키보드 Enter → 팝업, 마커 클릭 → 해당 목록 강조. 첫 그룹 팝업에서 하위 활동/메모 전체와 겹친 방문 선택을 확인했다. 상세 펼치기에서 메모·주소·관련 예약·외부/원본 링크를 확인했다.
- 모바일 문서 폭 375px/viewport 390px로 페이지 가로 넘침 없음. 날짜 칩만 가로 스크롤한다. 같은 좌표 그룹과 다른 상호를 임의 지리 오프셋 없이 선택할 수 있다.
- 지도 자동 범위 검증 중 기존 소수점 경도의 래핑 오차를 발견해 수정했다. 재검증에서 둘째 날 타일 줌 15로 8개 지점을 포함했고 단일 마커는 줌 14/선 0개, 빈 날짜는 지도 0개였다.
- 지도 날짜/보기 reload 유지, 다른 여행 기본 타임라인 및 독립 상태, API 갱신 후 첫날 마커 6개/선 3개로 재계산 확인. 오늘 탭의 시간 미정 계획/활동 표시도 확인했다.
- 실패 타일 URL 전용 서버에서 오류 안내·목록 6그룹 유지·재시도 로딩·타임라인 원본 20행 복귀/지도 제거 확인. 합성 API 401 뒤 PIN 화면/지도 0개 확인.

## 추가 설정/미검증

신규 환경변수나 라이브러리 설치는 필요 없다. 기존 Notion 읽기 토큰·PIN·Redis·세션·도시 시간대 설정을 유지한다. 추가된 네 속성의 이름/타입은 현재 앱 계약과 맞다. 미확인 좌표 48건은 사용자가 정확한 지점과 WGS84 여부를 확인해 Notion에서 보완해야 한다. 방문/이동 설명이 불명확하면 자동 추정하지 않으며 시간 미정 계획의 모든 방문 후보에 유효하고 고유한 순서를 입력한다.

Leaflet 1.9.4 + OSM 표준 타일을 기존대로 사용한다. React 19에 별도 래퍼가 필요 없고 공급자는 공개 빌드 변수로 교체 가능하다. [Leaflet 문서](https://leafletjs.com/reference-1.9.4.html)와 [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/)에 따른 출처·Referer·브라우저 캐시를 유지하고 사전 다운로드·지오코딩을 하지 않는다. 무료 무제한/SLA/중국 내 정상 접속을 보장하지 않는다. 현지 통신망·좌표계 정합성·운영 트래픽에 맞는 공급자의 요금/약관은 배포 전 확인이 필요하다.

이번 요청은 구현이며 운영 배포 승인을 포함하지 않는다. 코드 검토 후 별도 배포 요청 시 운영 환경으로 승격하고 실제 Notion 좌표 및 PIN으로 재검증한다.
